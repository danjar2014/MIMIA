# Petits Robots : apprendre la robotique et le code (6-12 ans, en français)

Application web installable (PWA), hors ligne. Aucun matériel nécessaire : le robot est simulé.
Lancer : start.bat (http://localhost:8082). Test des niveaux : `node test-levels.mjs`.
Pour installer sur tablette : héberger le dossier en HTTPS puis "Ajouter à l'écran d'accueil".

## Trois tranches d'âge (au choix au démarrage, modifiable)
- 6-8 ans : séquences d'instructions (avancer, tourner), sans texte à écrire.
- 8-10 ans : boucles (répéter), angles, formes géométriques.
- 10-12 ans : conditions (si), boucles conditionnelles (tant que), fonctions (Mon bloc), variables (taille).

## Contenu
- Découvrir le robot : 7 parties (cerveau, yeux, capteur de lumière, lampe, roues, batterie, haut-parleur) en leçon en 3 temps ; puis "capteur -> cerveau -> moteur" (sentir, penser, agir).
- Construire (la carte du robot) : une carte électronique avec des emplacements. On pose les éléments (batterie, moteurs, lampe, haut-parleur, capteur de distance, capteur de lumière, bouton) depuis le tiroir, puis on les relie au cerveau avec des fils en touchant deux points. Points colorés par famille (rouge = énergie, bleu = capteurs/entrées, vert = actions/sorties). 9 niveaux : l'énergie, les roues, la lampe, les yeux du robot, veilleur de nuit, robot alarme, plus et moins (polarité), robot explorateur, carte libre. Le robot réagit en direct, avec la liste "Ce que fait ton robot". Tests : `node test-board.mjs`.
- Programmer le cerveau (dans Construire) : 5 niveaux 🧠 (bouton→lampe, robot prudent, lampe qui clignote, deux capteurs, alarme à deux niveaux) où l'enfant écrit lui-même le programme du cerveau avec des blocs « si … alors … sinon » et des ordres (allumer la lampe, faire rouler les roues, faire sonner…). Le cerveau relit le programme à chaque tour : tout est éteint, puis les blocs sont lus de haut en bas. Les blocs lus s'allument en jaune ; un test lance plusieurs situations et montre la première qui échoue. Aussi disponible dans la carte libre (bouton « Cerveau : automatique / je le programme »). Tests : `node test-prog.mjs`.
- Aller plus loin (20 activités) : adapté du cours « Codage robotique, unité 12 » (NovaSavo, novasavo.com), reformulé et rendu interactif pour 6-12 ans.
  - ROS : fiches (nœuds, sujets, publier / s'abonner, services, fichier de lancement), quiz « mythe ou réalité », laboratoire de nœuds (brancher caméra → planificateur → moteurs avec des sujets, puis plusieurs abonnés), premier nœud « Hello World » en blocs, télécommande (le programme publie des messages, le robot écoute /cmd).
  - Apprentissage automatique : les 4 familles, le bras qui apprend par essais (renforcement, avec adaptation quand la pièce bouge), apprendre avec des exemples (supervisé : choisir des exemples variés), étapes d'un projet d'IA, bonnes habitudes.
  - Les 4 niveaux d'autonomie de l'IA, règles codées ou apprentissage ?, secteurs d'application et chiffres du cours, métiers, parcours d'apprentissage, démarrer avec ROS. Tests : `node test-adv.mjs`.
- Programmer : 17 niveaux sur grille (6 + 5 + 6). Chaque niveau introduit une seule idée nouvelle. Aux niveaux 10-12, un même programme doit réussir plusieurs parcours (généralisation).
- Capteurs : lumière (observer puis écrire la règle si/alors), distance (observer puis régler le seuil de freinage).
- Créer : dessiner avec le robot (défis avec modèle gris à recouvrir, ou dessin libre), composer une danse (lumières, notes, sauts), dessiner son propre parcours puis le programmer.
- Mon robot : personnaliser (nom, couleur, tête, yeux, antenne). Mes créations : tout se garde et se rejoue.

## Méthode Montessori appliquée
- Du concret vers l'abstrait : on découvre le robot réel avant de le programmer ; le programme est visible (blocs) et le robot l'exécute pas à pas, bloc surligné.
- Une difficulté à la fois, niveaux isolés.
- Contrôle de l'erreur intégré : pas de note ni de punition ; le robot montre son chemin (petits pas, ❗ sur l'obstacle), le modèle gris se superpose au dessin, indice sur demande.
- Liberté et rythme propre : tous les niveaux restent accessibles, le niveau conseillé est entouré ; création libre.
- Pas de score, pas de chrono. Pause respiration, rappel de pause doux, mode calme, grand affichage, voix.

## Fichiers
index.html, style.css, app.js (écrans), util.js, robot.js (dessin et parties), blocks.js (éditeur de blocs et interpréteur), levels.js + grid.js (niveaux et simulateur), draw.js, dance.js, labs.js, discover.js, advgames.js (fiches, quiz, tri, ordre, associations), advlabs.js (labos), boardlogic.js (règles de la carte), build.js (carte interactive).
- La mémoire du cerveau : une petite boîte qui retient OUI ou NON d'un tour à l'autre. Blocs « retenir : OUI », « retenir : NON », « changer la mémoire », conditions « la mémoire dit OUI/NON » et « le bouton vient d'être appuyé ». 2 niveaux : « Un bouton, deux ordres » (interrupteur) et « L'alarme qui se souvient ». Bouton « Effacer la mémoire » dans le test.
- La voix partout (`voice.js`) : chaque nouvel écran est lu (titre + consigne), toucher un bouton, un bloc, un point de la carte ou un texte le fait lire, tous les messages (bravo, erreurs, indices) sont lus tout seuls, « 🔊 Lire mon programme » dit le programme en phrases. En bas à droite : 🔊 lire la page, 🔈/🔇 voix oui/non. La voix utilise la synthèse vocale française du navigateur (réglage « Voix » aussi dans les réglages parents).
- Coder pour de vrai (`code.js`, `codeengine.js`, `codemissions.js`, `codeworker.js`) : un éditeur de vrai JavaScript avec commandes en français. 28 missions : 1) premiers mots (afficher, variables, calculs, for, if, %, fonctions avec return), 2) le robot sur la grille (avancer, tournerDroite, obstacleDevant, while, fonctions…), 3) le cerveau du robot (fonction `boucle()` qui lit distance(), lumiere(), boutonAppuye(), tic() et commande lampe(), roues(), hautParleur() ; variables = mémoire) + un atelier libre. Aides : touches ( ) { } " ; …, extraits for/if/while/function, indices progressifs puis solution, lecture du code à voix haute, voix pendant la saisie. Les erreurs sont traduites en français avec le numéro de ligne (guillemet oublié, parenthèse non fermée, majuscule, faute de frappe avec suggestion…). Le code s'exécute dans un Web Worker (boucle infinie arrêtée après 3,5 s). Tests : `node test-code.mjs`.
- Python (syntaxe simple) dans « Coder pour de vrai » (`pyinterp.js`, `codepy.js`) : les mêmes 28 missions, au choix en Python 🐍 (par défaut) ou en JavaScript 🟨 (bouton « Langage » en haut de chaque mission, le brouillon de chaque langage est gardé). Commandes en snake_case : `avancer()`, `tourner_gauche()`, `obstacle_devant()`, `lampe(True)`, `bouton_appuye()`… Le Python est un petit interpréteur écrit pour l'appli (ce n'est PAS CPython) : variables, if/elif/else, while, for…in range(), def/return/global, listes, textes, f-strings, `and/or/not`, `//`, `%`, `**`, les nombres à virgule affichés comme en Python (3.0). Pas de classes, import, try, dictionnaires, ni tranches. Erreurs en français avec la ligne exacte : deux points oubliés, décalage (indentation) manquant ou en trop, `=` au lieu de `==`, `else if` au lieu de `elif`, `print "x"` sans parenthèses, oubli de `global`… Tests : `node test-py.mjs`.
- Des blocs au vrai code (`blockcode.js`, `codeview.js`) : sous les blocs (niveaux « Programmer » et programme du cerveau), un panneau « 👀 Voir mon programme en vrai code » montre en direct le Python ou le JavaScript équivalent, avec lecture à voix haute et bouton « L'ouvrir dans l'éditeur ». Le code produit est vérifié par `node test-blockcode.mjs` (les 17 niveaux de blocs et 7 programmes du cerveau traduits réussissent leurs missions dans les deux langages). Menu « Coder pour de vrai » > « 0. Des blocs au vrai code ».
- Mon parcours (`parcours.js`, `learn.js`) : 11 rangs à débloquer, de Novice à Expert (🌱 Novice, 🔍 Curieux, 🛠️ Apprenti, ⚡ Bricoleur, 💡 Inventeur, 🧠 Programmeur, 🔗 Traducteur, ⌨️ Codeur, 🔧 Ingénieur, 🤖 Roboticien, 🏆 Expert), ~75 étapes. Le rang Novice (6 leçons « c'est quoi un robot / un ordre / un programme / l'ordre compte / cet écran ? / mon premier programme ») montre de quoi il s'agit avec « Ceci est… », « Cela veut dire… », des questions où l'on touche la bonne image, un petit robot à guider avec une flèche 👆, et une visite guidée de l'écran. Un rang s'ouvre quand le précédent est terminé, les étapes se font dans l'ordre, les cartes de l'accueil sont verrouillées au début. À la première ouverture : « Où en es-tu ? » (débutant / blocs / code) ; réglages parents : « Tout débloquer » et « Niveau de départ ». Fête à chaque rang terminé, diplôme imprimable à la fin. 3 défis d'expert en plus (bip-bop, nombre premier, veilleur complet). Tests : `node test-parcours.mjs`.
- Le Grand Projet (`project.js`, `projectdata.js`) : dernière étape du rang Expert. 5 étapes : ① choisir un projet (🧭 robot explorateur prudent ⭐⭐, ou 🛡️ robot gardien ⭐⭐⭐ avec mémoire d'alarme), ② choisir ses pièces (rien d'oublié, rien d'inutile, chaque erreur est expliquée), ③ monter la vraie carte et tout brancher, ④ écrire la fonction `boucle()` du cerveau en Python ou JavaScript, testée dans 9-10 situations successives, ⑤ la fiche projet (nom du robot, pièces, cahier des charges, essais rejoués pour de vrai, code) à imprimer ou garder dans « Mes créations ». Terminer le projet déclenche le diplôme d'expert. Reprise automatique si on quitte en cours de route. Tests : `node test-project.mjs`.
- Tableau de bord des parents (`stats.js`, `dashboard.js`) : réglages (appui long sur ⚙️) > « 📊 Tableau de bord ». Montre le rang et le % du parcours, le temps de jeu actif (aujourd'hui, 7 jours en barres, moyenne, série de jours), les compétences (bases, blocs, électronique, code…), les 11 rangs, les étapes « à surveiller » (beaucoup d'essais ratés ou de temps sans réussite), les dernières réussites, des conseils personnalisés. Outils : lire / imprimer / copier le résumé, limite de temps par jour (écran « C'est assez pour aujourd'hui », 15 min de plus accordées par un adulte après une multiplication), effacer les statistiques. Le temps ne compte que si l'enfant touche l'écran (pause après 60 s sans toucher). Tout reste dans le navigateur (localStorage), rien n'est envoyé. Tests : `node test-stats.mjs`.
- Code parent (`pin.js`) : 4 chiffres qui protègent les réglages (appui long sur ⚙️) et donc le tableau de bord, « Tout débloquer », la limite de temps, etc. Créé depuis Réglages > « Code parent » (saisie deux fois sur un pavé numérique, puis un code de secours à noter sur papier, affiché une seule fois). Après 5 erreurs : attente de 30 s, puis 1 min, 2 min… (15 min max). « Code oublié ? » : code de secours, ou en dernier recours effacement complet des données de l'appli. Quand le code existe, il remplace la multiplication pour accorder 15 minutes de plus à la fin de séance. Le code est stocké sous forme d'empreinte SHA-256 avec sel (pas en clair) ; les touches du pavé et le code de secours ne sont jamais lus à voix haute. Limite honnête : tout est dans le navigateur de l'appareil, un adulte qui sait vider le stockage du navigateur ou le modifier peut contourner ; c'est une protection contre un enfant, pas contre un expert. Tests : `node test-pin.mjs`.
- Idées tirées d'une étude des pages publiques de Mimo (aucun code ni contenu copié) :
  - 🎯 Défi du jour (`dailyq.js`, `daily.js`) : 3 questions de révision par jour (même défi toute la journée), tirées de ce que l'enfant a déjà appris : 26 questions de compréhension classées par rang, « le robot arrive-t-il au drapeau ? » (vérité calculée par simulation), « que va afficher ce programme ? » (vérité calculée en exécutant le code) et « à quelle ligne est la faute ? » (ligne donnée par le moteur). Aucun chrono, une erreur est expliquée gentiment et ne compte pas dans les « essais ratés » du suivi parents. Mode « m'entraîner encore » sans compter. Tests : `node test-daily.mjs`.
  - 🏅 Badges et série douce (`badges.js`) : 38 badges (étapes clés, 11 rangs, jours de jeu 3/7/14/30, défis du jour, « Je n'abandonne pas » pour une réussite après 6 essais ratés ou plus, « Je comprends mon code »). La série compte les jours de jeu : un jour de repos ne la casse pas (elle s'arrête après deux jours sans jouer) et un jour manqué n'est jamais présenté comme un échec. Les badges déjà mérités au moment de l'installation sont accordés en silence. Écran « Mes badges » + carte « Motivation » dans le tableau de bord parents. Tests : `node test-badges.mjs`.
  - 🧐 « Explique-moi » (`explain.js`) dans l'éditeur de code : décrit chaque ligne de Python ou JavaScript en français, avec des règles fixes (pas d'IA, toujours la même explication pour le même code), et lit l'explication à voix haute. Vérifié sur toutes les solutions de l'appli : aucune ligne sans explication. Tests : `node test-explain.mjs`.
- Accueil conversationnel (`onboard.js`) : au tout premier lancement, Bolt discute avec l'enfant en 10 petites étapes (salutation, prénom — facultatif —, âge, ce qui lui donne envie, mot rassurant, ce qu'il sait déjà, parcours conseillé, objectif du jour) puis l'emmène directement dans sa première leçon (ou à son point de départ). Observé sur l'accueil de Mimo (compte de test « Test », parcours Python) : salutation, prénom, profil, motivation, écran de réassurance, parcours conseillé, expérience, puis une offre payante que l'on n'a pas suivie. Aucune offre, aucune urgence artificielle ni chiffre non vérifié chez nous.
- XP et objectif du jour (`xp.js`) : 50 XP par étape réussie la première fois, +25 si aucune erreur. Objectif au choix : 50, 100 ou 200 XP (réglable dans les réglages parents). Après une étape : puce « +75 XP », écran « Tu as commencé une série ! » (première étape du jour, avec la semaine en pastilles), écran « Objectif du jour atteint ! » (anneau d'XP). Les écrans de récompense, de nouveau rang et de diplôme s'enchaînent en file d'attente. Bandeau « XP du jour + série » sur l'accueil et XP dans le tableau de bord parents. Tests : `node test-xp.mjs`.
- Mots à toucher (`tapcode.js`) dans « Coder pour de vrai » : sur les missions courtes (8 lignes de code au plus, hors défis d'expert et Grand Projet), l'enfant construit le programme ligne par ligne en touchant des mots au lieu de taper. Chaque ligne a quelques mots en trop (pièges : `rang` pour `range`, `7` pour `6`, `while` pour `for`…). « Vérifier » dit quel mot est faux (« le mot n°3 n'est pas le bon, regarde ce qui vient après… »), un mot faux devient rouge et s'enlève d'un geste, 💡 entoure le prochain mot. Chaque ligne réussie est expliquée en français (même moteur que « Explique-moi »). À la fin, le programme complet est écrit dans l'éditeur et lancé comme s'il avait été tapé. Choix « 🧩 En touchant des mots / ⌨️ En tapant » mémorisé ; par défaut « en touchant » pour les 6-8 ans. Inspiré de la mécanique d'exercice de Mimo, sans copie. Tests : `node test-tapcode.mjs` (toutes les missions éligibles, en Python et JavaScript : le code reconstruit est identique à la solution et réussit la mission).
- Le petit robot qui réagit (`mascot.js`) : en bas à gauche de chaque activité, un visage (la tête du robot de l'enfant : même forme, même couleur) qui réagit aux messages de l'appli : 😊 content (« Bien joué ! »), 😟 un peu inquiet mais gentil (« Pas tout à fait… », « Presque ! »), 🤔 réfléchit (indices), 🤩 fait la fête (victoire d'un programme, d'une mission). Une petite bulle donne un mot d'encouragement, sans doubler la voix. Il se branche sur les messages existants (classes ok / warn / hint) : toutes les activités en profitent sans modification (leçons, blocs, carte, code, mots à toucher, défi du jour). Il se cache pendant les écrans plein écran, disparaît si l'on coupe « Petit robot qui réagit » dans les réglages, s'immobilise en mode calme ou si le système demande moins d'animations. Toucher le petit robot : un mot gentil. Tests : `node test-mascot.mjs`.
- Test de placement de 5 questions (`dailyq.js`, `onboard.js`) : à l'accueil, « As-tu déjà programmé un peu ? » → « Non, je débute » (on commence au début) ou « Oui : je fais le petit test ». 5 questions du plus facile au plus difficile : l'ordre des ordres, suivre un robot sur une grille (le trajet est calculé par simulation), boucles et choix, lire un programme Python (le résultat vient de l'exécution du code), fonctions et mémoire. Chaque question a un bouton « Je ne sais pas » (très bien, pas de pénalité, ça évite de deviner) et le test s'arrête à la première erreur ou au premier « je ne sais pas ». On compte les bonnes réponses d'affilée : 0 → rang 1 Novice, 1 → rang 2, 2 → rang 4, 3 → rang 6, 4 → rang 8, 5 → rang 10 ; un coup de chance tardif ne remonte donc pas le niveau. L'enfant peut accepter ou préférer « tout reprendre au début ». Le résultat est montré aux parents (tableau de bord) ; réglages parents : « Niveau de départ » (les 11 rangs) et « 🎯 Refaire le test ». Tests : `node test-placement.mjs` (300 tirages : une seule bonne réponse, sorties et trajets re-vérifiés par le moteur ; effet sur les cartes et les étapes débloquées).
- Relecture d'ensemble et passe accessibilité (audit mesuré sur 8 écrans au format téléphone, guidé par la liste de contrôle du skill UI/UX) : correction d'une collision de nom de classe CSS (`.ring`) qui agrandissait la flèche de direction du robot sur toutes les grilles ; « Effacer la progression » efface maintenant tout le parcours (XP, badges, défis, projet, test de niveau) ; boutons principaux plus contrastés (vert #2e7d4f, 5:1) ; cibles tactiles d'au moins 44 px ; texte d'au moins 12 px ; anneau de focus visible au clavier ; textes secondaires plus lisibles.
- Nouveau look « dessin animé » (`scene.js`, `icons.js`, fin de `style.css`) : un décor animé multicolore derrière l'appli, qui change selon l'activité (☀️ ciel avec soleil souriant, nuages et ballons ; 🚀 espace avec étoiles, planète, lune et fusée ; 🔧 atelier avec engrenages et bulles ; 🎉 fête avec confettis), posé sous une feuille blanche vitrée pour que le texte reste toujours lisible. Boutons « argile » bombés qui s'enfoncent au toucher, icônes dessinées (14) à la place des emojis sur l'accueil. Nouvel accueil : un seul grand bouton « Continuer » (la prochaine étape du parcours) avec le visage du robot de l'enfant, trois tuiles (défi du jour, parcours, badges) et les autres activités repliées dans « Toutes les activités ». Lecteur de leçon : barre de progression en segments et bouton principal collé en bas. Le décor est composé uniquement de formes SVG animées par transform/opacity (60 images/s mesurées), se fige en mode calme et si le système demande moins d'animations, se coupe dans les réglages (« Décor animé »), ne charge rien sur Internet. Police : pile arrondie système (Baloo 2 / Fredoka / Nunito / Trebuchet si présents) sans appel à Google Fonts (vie privée des enfants, usage hors ligne). Tests : `node test-design.mjs`.
- Voix « sans bavardage » (`util.js` speak, `voice.js`) : la voix ne lit plus tout et n'importe quoi. Trois modes dans les réglages parents (« Ce que la voix lit ») : **Consigne et résultat** (par défaut) : à chaque nouvel écran, le titre et la consigne (un seul message court) ; ensuite seulement les résultats (bravo, erreur, indice) ; rien ne se lit quand on touche un bouton, un bloc ou un texte, ni pendant la frappe du code ; les listes (parcours, badges) ne lisent que leur titre. **Seulement avec le bouton 🔊** : silence tant qu'on n'appuie pas ; 🔊 relit la consigne, les réponses possibles et le dernier résultat. **Tout ce qu'on touche** : l'ancien comportement, pour ceux qui en ont besoin. Règle commune : priorités (ambiance 0 < consigne 1 < résultat 2 < demandé 3), une phrase n'est jamais redite dans les 15 s ni quand elle est presque identique à la précédente, un résultat n'est pas coupé par une consigne, un nouvel écran interrompt l'ancien, les textes longs sont raccourcis aux premières phrases (240 caractères) sauf si l'enfant le demande. Tests : `node test-voice.mjs`.
